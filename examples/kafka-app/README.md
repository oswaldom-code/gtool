# kafka-app — sample application under test

A minimal Go service used to exercise the `gtool` pipeline with Kafka (broker
mock → app → Karate tests → cleanup). On startup it reads `data/orders.json` and
publishes each order to the `orders` topic; the Karate test consumes them with
the launcher's `kafka/ConsumeMessage.feature` and validates their values.

## Layout

```
kafka-app/
├── component-config.yml          # gtool config: kafka mock, app image, Karate tests
├── data/orders.json              # messages the app publishes on startup
├── Dockerfile
├── main.go
└── test/component/
    ├── features/orders.feature   # consumes orders and validates them
    └── reports/                  # generated by gtool test (git-ignored)
```

Configuration is read from environment variables: `KAFKA_BROKERS`, `TOPIC`,
`DATA_FILE`, `PORT`.

## Run it with gtool

```bash
# 1. Build the app image (gtool runs it as a container)
docker build -t kafka-app:latest .

# 2. From this directory, run the full pipeline
gtool test --config component-config.yml
```

`gtool test` starts a single-node Kafka broker (creating the `orders` topic
declared in `component-config.yml`), starts this app, runs the Karate features
in `test/component/features/`, and tears everything down.

## Networking notes

- **App → broker:** Kafka clients reconnect to the address the broker
  advertises, so the app uses the broker's container listener on
  `host.docker.internal:9094`, which is advertised with that same address.
- **Tests → broker:** the Karate launcher runs on the host network. Its
  `kafka/*.feature` helpers expect the broker on `localhost:9092`, which is why
  the mock is configured with `port: "9092"`.
