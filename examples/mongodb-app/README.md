# mongodb-app — sample application under test

A minimal Go service used to exercise the `gtool` pipeline with MongoDB (MongoDB
mock → app → Karate tests → cleanup). On startup it reads `data/customers.json`
and inserts each customer into the `customers` collection; the Karate test reads
them with the launcher's `launcher.mongo.MongoClient` and validates their
values.

## Layout

```
mongodb-app/
├── component-config.yml             # gtool config: mongodb mock, app image, Karate tests
├── data/customers.json              # documents the app inserts on startup
├── Dockerfile
├── main.go
└── test/component/
    ├── features/customers.feature   # finds each customer and validates it
    └── reports/                     # generated by gtool test (git-ignored)
```

Configuration is read from environment variables: `MONGO_URI`,
`MONGO_DATABASE`, `COLLECTION`, `DATA_FILE`, `PORT`.

## Run it with gtool

```bash
# 1. Build the app image (gtool runs it as a container)
docker build -t mongodb-app:latest .

# 2. From this directory, run the full pipeline
gtool test --config component-config.yml
```

`gtool test` starts MongoDB, starts this app, runs the Karate features in
`test/component/features/`, and tears everything down. MongoDB assigns an `_id`
to every inserted document, so the test ignores it with `'#ignore'`.

## Networking notes

- **App → MongoDB:** the app container reaches the host-published MongoDB
  through `host.docker.internal`, which gtool maps to the host gateway.
- **Tests → MongoDB:** the Karate launcher runs on the host network, so
  `MongoClient` connects to `mongodb://localhost:27017`.
