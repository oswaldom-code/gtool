# mountebank-app — sample application under test

A minimal Go service used to exercise the `gtool` pipeline with Mountebank
(imposter mock → app → Karate tests → cleanup). `GET /greeting` calls an
external greeting API and returns its message as `{"greeting": "..."}`; in the
component test that API is a Mountebank imposter.

## Layout

```
mountebank-app/
├── component-config.yml                  # gtool config: mountebank mock, app image, Karate tests
├── Dockerfile
├── main.go
└── test/component/
    ├── features/greeting.feature         # calls the app and validates the greeting
    ├── mocks-data/mountebank/
    │   └── greeting-api.json             # imposter on :4545 stubbing GET /greeting
    └── reports/                          # generated by gtool test (git-ignored)
```

Configuration is read from environment variables: `GREETING_API_URL`, `PORT`.

## Run it with gtool

```bash
# 1. Build the app image (gtool runs it as a container)
docker build -t mountebank-app:latest .

# 2. From this directory, run the full pipeline
gtool test --config component-config.yml
```

`gtool test` starts Mountebank, loads every `*.json` imposter from
`test/component/mocks-data/mountebank/` and publishes the imposter ports, starts
this app, runs the Karate features in `test/component/features/`, and tears
everything down.

## Networking notes

- **App → imposter:** the app container reaches the host-published imposter
  port through `host.docker.internal`, which gtool maps to the host gateway.
- **Tests → app:** the Karate launcher runs on the host network, so it reaches
  the app at `localhost:8080`.
