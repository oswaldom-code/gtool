# mysql-app — sample application under test

A minimal Go service used to exercise the `gtool` pipeline with MySQL (MySQL
mock → app → Karate tests → cleanup). On startup it reads `data/books.json`,
creates the `books` table and inserts each book as a row; the Karate test reads
them with the launcher's `launcher.mysql.MySqlClient` and validates their
values.

## Layout

```
mysql-app/
├── component-config.yml             # gtool config: mysql mock, app image, Karate tests
├── data/books.json                  # rows the app inserts on startup
├── Dockerfile
├── main.go
└── test/component/
    ├── features/books.feature       # reads each book row and validates it
    └── reports/                     # generated by gtool test (git-ignored)
```

Configuration is read from environment variables: `MYSQL_DSN`, `DATA_FILE`,
`PORT`.

## Run it with gtool

```bash
# 1. Build the app image (gtool runs it as a container)
docker build -t mysql-app:latest .

# 2. From this directory, run the full pipeline
gtool test --config component-config.yml
```

`gtool test` starts MySQL, starts this app, runs the Karate features in
`test/component/features/`, and tears everything down. The MySQL mock does not
load schema scripts, so the app creates its own table on startup.

## Networking notes

- **App → MySQL:** the app container reaches the host-published MySQL through
  `host.docker.internal`, which gtool maps to the host gateway.
- **Tests → MySQL:** the Karate launcher runs on the host network, so
  `MySqlClient` connects to `jdbc:mysql://localhost:3306/test`.
