# pubsub-app — sample application under test

A minimal Go service used to exercise the `gtool` pipeline with Pub/Sub
(emulator mock → app → Karate tests → cleanup). On startup it reads
`data/orders.json` and publishes each order to the `orders` topic; the Karate
test consumes them with the launcher's `pubsub/ConsumeMessage.feature` and
validates their values.

## Layout

```
pubsub-app/
├── component-config.yml          # gtool config: pubsub mock, app image, Karate tests
├── data/orders.json              # messages the app publishes on startup
├── Dockerfile
├── main.go
└── test/component/
    ├── features/orders.feature   # consumes orders-sub and validates the orders
    └── reports/                  # generated by gtool test (git-ignored)
```

Configuration is read from environment variables: `PUBSUB_EMULATOR_HOST`,
`PUBSUB_PROJECT_ID`, `TOPIC`, `DATA_FILE`, `PORT`. The official Go client
targets the emulator automatically when `PUBSUB_EMULATOR_HOST` is set.

## Run it with gtool

```bash
# 1. Build the app image (gtool runs it as a container)
docker build -t pubsub-app:latest .

# 2. From this directory, run the full pipeline
gtool test --config component-config.yml
```

`gtool test` starts the Pub/Sub emulator (creating the `orders` topic and the
`orders-sub` subscription declared in `component-config.yml`), starts this app,
runs the Karate features in `test/component/features/`, and tears everything
down.

## Networking notes

- **App → emulator:** the app container reaches the host-published emulator
  through `host.docker.internal`, which gtool maps to the host gateway.
- **Tests → emulator:** the Karate launcher runs on the host network; gtool
  sets `PUBSUB_EMULATOR_HOST=127.0.0.1:<pubsub port>` so the launcher's Pub/Sub
  helpers reach the emulator.
