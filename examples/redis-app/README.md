# redis-app — sample application under test

A minimal Go service used to exercise the `gtool` pipeline with Redis (Redis
mock → app → Karate tests → cleanup). On startup it reads `data/products.json`
and stores each product as `product:<id>`; the Karate test reads the keys with
the launcher's `launcher.redis.RedisClient` and validates their values.

## Layout

```
redis-app/
├── component-config.yml            # gtool config: redis mock, app image, Karate tests
├── data/products.json              # products the app stores on startup
├── Dockerfile
├── main.go
└── test/component/
    ├── features/products.feature   # reads the keys and validates the products
    └── reports/                    # generated by gtool test (git-ignored)
```

Configuration is read from environment variables: `REDIS_ADDR`, `DATA_FILE`,
`PORT`.

## Run it with gtool

```bash
# 1. Build the app image (gtool runs it as a container)
docker build -t redis-app:latest .

# 2. From this directory, run the full pipeline
gtool test --config component-config.yml
```

`gtool test` starts Redis, starts this app, runs the Karate features in
`test/component/features/`, and tears everything down.

## Networking notes

- **App → Redis:** the app container reaches the host-published Redis through
  `host.docker.internal`, which gtool maps to the host gateway.
- **Tests → Redis:** the Karate launcher runs on the host network, so
  `RedisClient` connects to `localhost:6379`.
