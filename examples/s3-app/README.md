# s3-app — sample application under test

A minimal Go service used to exercise the `gtool` pipeline with S3 (Floci mock →
app → Karate tests → cleanup). On startup it uploads `data/report.json` to
`s3://reports/orders/report.json`; the Karate test downloads it with the
launcher's `launcher.s3.S3Client` and validates its values.

## Layout

```
s3-app/
├── component-config.yml             # gtool config: floci mock with the reports bucket, app image, Karate tests
├── data/report.json                 # object the app uploads on startup
├── Dockerfile
├── main.go
└── test/component/
    ├── features/report.feature      # downloads the object and validates it
    └── reports/                     # generated by gtool test (git-ignored)
```

Configuration is read from environment variables: `S3_ENDPOINT`, `AWS_REGION`,
`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `BUCKET`, `OBJECT_KEY`,
`DATA_FILE`, `PORT`.

## Run it with gtool

```bash
# 1. Build the app image (gtool runs it as a container)
docker build -t s3-app:latest .

# 2. From this directory, run the full pipeline
gtool test --config component-config.yml
```

`gtool test` starts Floci and creates the `reports` bucket, starts this app,
runs the Karate features in `test/component/features/`, and tears everything
down. Floci does not validate credentials by default, so any non-empty values
work.

## Networking notes

- **App → Floci:** the app container reaches the host-published Floci through
  `host.docker.internal`, which gtool maps to the host gateway. Path-style
  addressing keeps the bucket in the URL path, so no per-bucket DNS is needed.
- **Tests → Floci:** the Karate launcher runs on the host network, so
  `S3Client` connects to `http://localhost:4566`.
